All data is synthetic, generated by Day 7's generator and this chapter's script. In a real
engagement the rows come from the records named in section 3.

## 1. What this pack measures, and why now

The baseline for the four metrics the business case and the pre-registered definitions depend on,
measured before the pilot touches any production file. After the pilot starts it cannot be measured
again.

## 2. The ops report, read before counting

| Report figure | What it counts | Caveat carried forward |
|---|---|---|
| median turnaround 9.2 days | core received date to sanction, sanctioned files, last quarter | the received date is not the signing date; resubmissions sometimes reset it; withdrawn and rejected files excluded |
| 4.5 analyst hours per file | the team leads' estimate (2024 staffing note) | never timed |
| 31 percent sent back | core status "returned to branch" | phone and WhatsApp chases not counted; repeat send-backs counted once |

## 3. Method

| Item | Choice |
|---|---|
| clock | the customer's: signed at branch to decision (sanction, rejection, withdrawal) |
| frame | every new file on the SFTP arrival log in the fortnight of the 6th to the 19th (no month-end, no festival): 700 files |
| strata | 6 branch clusters x 4 products = 24 |
| allocation | proportional, floor of 2 per stratum, largest remainder; weights = stratum size / sampled |
| sample | 120 files, seed 9; list fixed before any file was opened; no replacements, no re-draw |
| turnaround and outcome | retrospective: form signing date, SFTP log, core record-creation time (first opened), core decision date and status history, tracker text |
| hours | prospective timing log in discovery weeks 2 and 3 on sampled files; first two days discarded; ten files shadowed end to end as a check |
| second counter | 12 files (10 percent) counted twice; disagreements resolved by written rule |
| intervals | 95 percent; stratified normal for means and rates with finite population correction; stratified bootstrap (2,000) for the median |

Simplification in the synthetic version: the script attaches the timing log to the same 120 files as
the record reconstruction. In the engagement the timing sample is drawn the same way from files
opened during the timing fortnight.

**Rule agreed with the compliance head (from the second count):** an address proof counts as present
only if it is in the file of record, legible, and on her signed list of acceptable alternatives. A
photo on an analyst's phone is not present.

## 5. Results

| Metric | Ops report | Hand count | 95% interval | Report consistent? |
|---|---|---|---|---|
| median turnaround, days | 9.2 | 9.1 | 8.7 to 9.7 | yes |
| analyst hours per file | 4.5 | 4.6 | 4.5 to 4.7 | yes |
| send-back rate | 31% | 28% | 21% to 35% | yes |
| addressable hours per file (re-key + completeness + chasing) | - | 1.59 | 1.52 to 1.66 | new |
| decided with a mandatory document missing | - | 4.1% | 0.9% to 7.2% | new; census of 700 recommended |
| withdrawn by the customer | - | 10.1% | 5.2% to 14.9% | new |
| recall of today's human completeness check | - | 87% | (5 of 38 incomplete sampled files not sent back) | new |
| approval rate among decided files | - | 81% | | new |

Where the days go (means): transit 1.1 · **queue 6.4** · work 1.6 · branch wait 0.9 (about 3 days on
each file sent back). Where the hours go (means): re-keying 0.97 · completeness 0.35 · chasing 0.27 ·
assessment and memo 3.01.

## 6. What the pack concludes

1. The monthly report is consistent with the hand count on all three figures and can be used as a
   trend, with the caveats in section 2 written beside it.
2. Six of the nine days are queue: files waiting to be opened. The analysts' "a day and a half" is the
   work stage. Utilisation is about 97 percent.
3. Intake and completeness are 1.59 hours a file, above the 1.2 that Day 4's pick required. The pick
   stands.
4. Today's process decides about 4 in 100 files with a mandatory document missing, and about 10 in
   100 customers withdraw. Neither appears in any report.

## 7. What this pack is not

Not the business case (`godavari-business-case.md`), not the definitions (`godavari-metric-definitions.md`),
not a measurement of the system (Day 37). No subgroup below product or cluster level is reported.
